技术权衡 · Trade-offs

稀疏不是银弹：三大代价必须警惕

MoE + 稀疏注意力并非没有代价。押注该路线前，需清晰认识三个关键权衡。

① 路由不稳定

极低激活率下，门控网络（gating network）的微小波动会导致专家选择偏移，引发输出不一致。V4 通过流形约束超连接（Manifold-Constrained Hyper-Connections）部分缓解，但仍需在 prompt 层面做兼容性测试。

② 显存墙

虽然激活参数少，但所有专家权重仍需常驻显存。1.6T 参数的 V4 Pro 在 FP8 下需要约 3.2TB 显存——这意味着单机部署不可行，必须走专家并行 + 张量并行的分布式推理。

③ 长文本回归

稀疏注意力在 32K 以下优势显著，但在 256K+ 的极端长文本场景，仍可能因「漏掉关键 token 块」导致needle-in-haystack 任务掉点。NSA 通过硬件对齐设计部分缓解，但仍是 open problem。

④ 工程复杂度

MoE 推理需要专家调度器、负载均衡器、通信优化三层基建，远比 Dense 模型复杂。中小团队需依赖 vLLM/SGLang 等开源框架才能跑起来。

决策建议：若你的场景是 RAG/Agent/编程辅助（上下文 ≤ 128K，延迟敏感）→ MoE + 稀疏注意力是首选。若场景是 超长文档分析/法律合同审查（≥ 256K，强连贯性）→ Dense + 全注意力 + KV 压缩（如 MLA）可能更稳。
深度技术 · Deep Dive

NSA 稀疏注意力实现细节：从算法到 CUDA Kernel

DeepSeek 在 2025 年 2 月发布的 NSA（Native Sparse Attention）是首个硬件对齐且原生可训练的稀疏注意力方案，论文已被 ACL 2025 接收为最佳论文。它的核心创新不在「稀疏」本身，而在「让稀疏与 GPU Tensor Core 的访存模式完美匹配」。

三路并行架构（Three-Branch Parallelism）

NSA 把注意力分解为三条独立计算路径，并行执行而非串行：

  • ① 压缩分支（Compression Branch）：把局部连续的 32 个 token 通过可学习的 MLP 压缩为 1 个聚合表示，捕获粗粒度全局信息。这一支复用了 FlashAttention 的分块思路。
  • ② 选择分支（Selection Branch）：基于压缩后的表示，用 top-k 选择算法选出最重要的 64 个 block（每 block 64 token），覆盖细粒度重要位置。这是 NSA 与传统稀疏注意力的核心差异。
  • ③ 滑动窗口分支（Sliding Window Branch）：保留最近 256 个 token 的完整注意力，保证局部上下文绝对不丢失——这是 FlashAttention 作者 Tri Dao 在评审中特别强调的「安全网」。

硬件对齐的关键设计

NSA 的算术强度（arithmetic intensity）精确控制在 GPU Tensor Core 的临界点附近——既不会因为访存不足而「饿死」计算单元，也不会因为计算过重而「挤爆」寄存器。具体实现上：

  • 块大小固定为 32/64：与 H100/B200 Tensor Core 的 16×16 子块矩阵乘天然对齐，避免 bank conflict。
  • GQA 兼容：支持 Grouped Query Attention，可减少 KV Cache 70% 占用。
  • 动态编译：编译期根据序列长度自动选择最优的三路分支权重。

NSA 的 PyTorch 伪代码实现

import torch
import torch.nn.functional as F

def native_sparse_attention(Q, K, V, 
                              block_size=32,    # 压缩块大小
                              sel_block=64,     # 选择块大小
                              window=256,       # 滑动窗口
                              top_k=16):        # 选中 block 数量
    """
    NSA 三路并行注意力简化实现
    Q, K, V: [B, H, L, D]
    """
    B, H, L, D = Q.shape
    
    # ========== 分支1：压缩分支 ==========
    # 把局部连续 block_size 个 token 压缩为 1 个表示
    K_comp = K.reshape(B, H, L//block_size, block_size, D).mean(dim=-2)
    V_comp = V.reshape(B, H, L//block_size, block_size, D).mean(dim=-2)
    # 压缩后注意力: O((L/block_size)²)
    attn_comp = F.scaled_dot_product_attention(Q, K_comp, V_comp)
    
    # ========== 分支2：选择分支 ==========
    # 用压缩表示打分，选出 top_k 个最重要的 block
    importance = Q @ K_comp.transpose(-2, -1)  # [B, H, L, L/block_size]
    top_indices = importance.topk(top_k, dim=-1).indices  # [B, H, L, top_k]
    
    # 收集选中的 K, V
    selected_K = gather_blocks(K, top_indices, sel_block)  # [B, H, L, top_k*sel_block, D]
    selected_V = gather_blocks(V, top_indices, sel_block)
    attn_sel = F.scaled_dot_product_attention(Q, selected_K, selected_V)
    
    # ========== 分支3：滑动窗口 ==========
    K_win = sliding_window(K, window)
    V_win = sliding_window(V, window)
    attn_win = F.scaled_dot_product_attention(Q, K_win, V_win)
    
    # ========== 加权融合 ==========
    # 三路权重由可学习参数决定
    w_comp, w_sel, w_win = 0.3, 0.5, 0.2  # 实际可通过 nn.Parameter 学习
    return w_comp * attn_comp + w_sel * attn_sel + w_win * attn_win

def gather_blocks(x, indices, block_size):
    """按索引收集选中的块"""
    B, H, L, D = x.shape
    x_blocks = x.reshape(B, H, L//block_size, block_size, D)
    # 高级索引收集
    return x_blocks.index_select(dim=-3, index=indices.flatten()).reshape(B, H, -1, D)
核心结论：NSA 不是又一个「稀疏注意力变体」，而是把稀疏决策从「人工设计规则」升级到「可学习路由」的范式转变。它的真正威力在于：三路并行结构在 64K 上下文下实现了 9 倍训练加速+ 4 倍解码加速，而精度损失仅 0.3%——这是稀疏注意力第一次在「效率」和「效果」两个维度同时达到工业级可用标准。
实战手册 · Engineering Playbook

KV Cache 压缩实战：从 PagedAttention 到 SnapKV

KV Cache 是大模型推理的「内存黑洞」——LLaMA-7B 在 32K 上下文下 KV Cache 高达 16GB，超过模型权重本身。本章拆解工业界最主流的四种 KV Cache 压缩方案。

方案 1：PagedAttention（vLLM 核心）

UC Berkeley 2023 SOSP 最佳论文，现已成为 vLLM/TGI/SGLang 等主流推理引擎的事实标准。

  • 核心思想：借鉴操作系统虚拟内存分页机制——把 KV Cache 切成固定大小的物理 block（默认 16 token/block），通过页表维护逻辑→物理映射。
  • 收益：内存碎片从 ~60% 降到 <4%；吞吐量提升 14-24 倍（vs HuggingFace Transformers）。
  • 局限：不减少单序列的 KV 总量，只解决多序列批处理的内存效率问题。

方案 2：FlashAttention / FlashAttention-2/3

Tri Dao 的「用 IO 复杂度换计算复杂度」代表作：

  • 核心思想：分块计算 attention，不存中间结果到 HBM，通过 online softmax 在 SRAM 内完成完整计算。
  • FlashAttention-2：重排 warp 工作分配，2-4 倍前向加速。
  • FlashAttention-3（2024）：针对 H100 FP8 Tensor Core 优化，1.5-2 倍进一步加速，且首次在 FP8 下保持数值稳定。
  • 关键点：FlashAttention 是注意力计算加速，不是KV 压缩，但它是 PagedAttention/SnapKV 的基础。

方案 3：GQA / MQA / MLA（结构压缩）

通过共享 KV 头减少 KV Cache 总量：

  • MQA（Multi-Query）：所有 Q 头共享 1 个 KV 头——KV 减少到 1/N（H=32 时减少 96.875%），但精度损失明显。
  • GQA（Grouped Query）：分组共享（如 8 组共享 1 KV）——Llama-2/3、Mistral 主流方案，平衡精度与效率。
  • MLA（Multi-Head Latent Attention）：DeepSeek 首创——把 KV 压缩到低维潜空间（如 4×压缩），再用解耦矩阵恢复——KV Cache 减少 93.3%，且精度反超 GQA。DeepSeek-V2/V3 全系使用。

方案 4：SnapKV（动态压缩，2024 新星）

SnapKV 是 2024 年最具影响力的 KV 压缩论文，思路独到：

  • 核心洞察：模型在生成前几个 token 时就能判断「后面要关注哪些位置」——通过观察 attention 权重的「投票」。
  • 核心算法：用一个聚类查询向量扫描全 KV Cache，把 attention 权重高的 block 保留下来。
  • 效果：在 16K 上下文、保留 12% KV 的情况下，精度保留 97%；推理速度提升 3.2×。
  • 局限：压缩发生在Prefill 阶段，对 Prefill 时延敏感的场景不友好。

SnapKV 的核心代码片段

import torch

class SnapKVCompressor:
    """SnapKV: 用聚类查询做 KV Cache 动态压缩"""
    
    def __init__(self, window_size=64, max_capacity=512, kernel_size=5):
        self.window_size = window_size  # 保留最近 window_size 个 token
        self.max_capacity = max_capacity  # 最大保留 block 数
        self.kernel_size = kernel_size  # 局部聚类窗口
    
    def select_kv_blocks(self, query_cluster, key_cache):
        """
        Args:
            query_cluster: [B, H, N_q, D] 聚类查询向量
            key_cache:     [B, H, L, D]    完整 KV Cache
        Returns:
            selected_indices: [B, H, max_capacity] 要保留的 block 索引
        """
        B, H, L, D = key_cache.shape
        
        # Step 1: 用聚类查询对所有位置打分
        # attention weights = softmax(Q · K^T / sqrt(D))
        scores = torch.einsum('bhqd,bhkd->bhqk', query_cluster, key_cache)
        scores = scores.softmax(dim=-1).sum(dim=-2)  # 聚合所有查询
        
        # Step 2: 滑动窗口池化（保留局部峰值）
        # 这是 SnapKV 的关键技巧：相邻位置的重要性高度相关
        scores_pool = F.avg_pool1d(
            scores, 
            kernel_size=self.kernel_size, 
            stride=1, 
            padding=self.kernel_size//2
        )
        
        # Step 3: 永远保留最近 window_size 个位置
        scores_pool[:, :, -self.window_size:] = float('inf')
        
        # Step 4: Top-k 选择最重要的位置
        _, top_indices = scores_pool.topk(self.max_capacity, dim=-1)
        top_indices, _ = top_indices.sort(dim=-1)  # 保持时序
        
        return top_indices
    
    def compress(self, key_cache, value_cache, query_cluster):
        """压缩 KV Cache"""
        indices = self.select_kv_blocks(query_cluster, key_cache)
        
        # 按索引收集被保留的 K, V
        B, H = key_cache.shape[:2]
        idx_expanded = indices.unsqueeze(-1).expand(B, H, self.max_capacity, key_cache.shape[-1])
        
        K_compressed = key_cache.gather(dim=-2, index=idx_expanded)
        V_compressed = value_cache.gather(dim=-2, index=idx_expanded)
        
        # 压缩率: L → max_capacity (例如 16K → 512)
        compression_ratio = self.max_capacity / key_cache.shape[-2]
        print(f"KV Cache 压缩率: {compression_ratio:.2%}")
        
        return K_compressed, V_compressed
工程建议：生产环境推荐 PagedAttention + FlashAttention-3 + GQA/MLA「三件套」组合——前三者解决内存管理和计算效率，不损失精度；SnapKV 适合超长上下文（>64K）且可容忍 1-3% 精度下降的场景。在 2026 H2，预计会出现「SnapKV + MLA」的端到端融合方案，进一步压低 KV 占用至 1% 以下。

推测解码：用「草稿模型」撬动 3 倍推理加速

推测解码（Speculative Decoding）是 2023 年以来最重要的「无精度损失」推理加速技术。Google 首次提出，CMU/清华/MIT 团队在工业落地中把它从「论文原型」推进到「生产级引擎」。

核心原理：「小模型猜 + 大模型验」

推测解码的本质是把串行解码并行化：

  1. Step 1（草稿）：用小型草稿模型（如 7B）连续生成 γ 个候选 token（γ 通常 4-8）。
  2. Step 2（验证）：用大型目标模型（如 70B）一次性并行验证这 γ 个 token。
  3. Step 3（接受/拒绝）：按目标模型的真实概率决定接受哪些 token——被拒绝的 token 重新采样。
  4. 数学保证：接受/拒绝采样机制严格保证输出分布与原始模型一致，零精度损失。

三大主流方案深度对比

① SpecInfer（CMU，2023）

  • 创新点：提出 Tree-based Attention——草稿模型的多个候选 token 组织成树结构，目标模型一次验证整棵树。
  • 加速比：2.6-3.2×（基于 LLaMA-7B/70B）
  • 落地：已被 vLLM 集成（v0.4.0+），是当前生产环境最成熟的方案。

② EAGLE / EAGLE-2（MIT，2024）

  • 创新点：不用独立草稿模型，而是在目标模型的中间层训练一个轻量「自回归头」（auto-regression head），单次前向即可预测下一步。
  • EAGLE-2 升级：引入 Dynamic Draft Tree——根据当前 context 动态调整树结构，加速比从 3× 提到 4-5×。
  • 优势：不需要单独部署草稿模型，工程复杂度低。

③ Medusa（MIT，2023-2024）

  • 创新点：在目标模型的最后 hidden state 上并联 K 个解码头，每个头预测未来第 i 个 token（i=1..K）。
  • Medusa-2：加入 Tree Attention + Typical Acceptance，推理加速比稳定 2.8-3.5×。
  • 优势：完全无草稿模型，部署最简单。

EAGLE-2 核心代码片段

import torch
import torch.nn as nn

class EAGLEHead(nn.Module):
    """EAGLE: 在目标模型中间层训练一个轻量自回归头"""
    
    def __init__(self, target_hidden_size, vocab_size, num_layers=1):
        super().__init__()
        # 轻量自回归头：1 层 Transformer Decoder
        decoder_layer = nn.TransformerDecoderLayer(
            d_model=target_hidden_size,
            nhead=8,
            dim_feedforward=target_hidden_size * 2,
            batch_first=True
        )
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers)
        # 输出词表分布
        self.lm_head = nn.Linear(target_hidden_size, vocab_size, bias=False)
    
    def forward(self, target_hidden_states, target_embeddings):
        """
        Args:
            target_hidden_states: [B, L, D] 目标模型中间层输出
            target_embeddings:    [B, L, D] 目标模型 token embedding
        Returns:
            next_token_logits: [B, L, V] 预测下一个 token 的分布
        """
        # 用 token embedding 作为 decoder 输入
        # 用目标 hidden state 作为 cross-attention 的 KV
        predicted = self.decoder(
            tgt=target_embeddings,
            memory=target_hidden_states
        )
        return self.lm_head(predicted)


class DynamicDraftTree:
    """EAGLE-2 动态树结构生成器"""
    
    def __init__(self, max_depth=6, top_k_per_node=4):
        self.max_depth = max_depth
        self.top_k = top_k_per_node
    
    def build_tree(self, draft_probs):
        """
        根据草稿模型的概率分布构建动态验证树
        draft_probs: [B, L, V] 每个位置的概率分布
        """
        tree = []  # list of (depth, token_id)
        
        # 从第一个位置开始，按概率展开 top-k 节点
        current_nodes = [(0, draft_probs[:, 0].argmax(dim=-1))]
        
        for depth in range(self.max_depth):
            next_nodes = []
            for parent_depth, parent_token in current_nodes:
                # 拿到 parent 的条件概率分布
                cond_prob = draft_probs[:, parent_depth].gather(
                    dim=-1, index=parent_token.unsqueeze(-1)
                )
                # 选出 top-k 续写
                top_k_tokens = cond_prob.topk(self.top_k, dim=-1).indices
                for tok in top_k_tokens:
                    next_nodes.append((depth + 1, tok))
            tree.extend(next_nodes)
            current_nodes = next_nodes
        
        return tree  # 目标模型一次并行验证整棵树
落地建议：对于单模型部署场景（不想额外维护草稿模型），推荐 EAGLE-2——它是当前加速比最高（4-5×）且无外部依赖的方案。对于已经有蒸馏小模型的场景，SpecInfer 是性价比之选。两者都已在 vLLM/SGLang 中原生支持，集成成本极低。2026 年的关键趋势是「推测解码 + MoE」——在 DeepSeek-V3 上 EAGLE-2 已实现 5.6× 加速，因为 MoE 的稀疏激活天然降低了草稿成本。

MoE 推理路由优化：DeepSeek-V3 vs Qwen3 vs Mixtral 三巨头对决

2025 年是 MoE 架构「大分化」的一年——DeepSeek-V3（256 专家）、Qwen3-235B-A22B（128 专家）、Mixtral 8x22B（8 专家）代表了三种截然不同的设计哲学。本章从路由策略、激活效率、推理性能三个维度做硬核对决。

1. 路由策略：稀疏 vs 稠密 vs 共享

DeepSeek-V3：细粒度专家 + 共享专家

  • 架构：256 个细粒度专家（每专家约 2B 参数）+ 1 个共享专家。
  • 路由：每个 token 激活 8 个专家（top-8 路由）+ 共享专家永远激活。
  • 创新：首次把专家拆分到比传统 MoE 细 16 倍的粒度，允许更灵活的组合。
  • 激活率：37B / 671B = 5.5%。

Qwen3-235B-A22B：128 专家 + MoE 升级版

  • 架构：128 个专家，每专家约 1.8B 参数。
  • 路由：每个 token 激活 8 个专家（top-8）。
  • 创新：支持「思考模式」/「非思考模式」动态切换——同一模型既可做快速响应又可做深度推理。
  • 激活率：22B / 235B = 9.4%。

Mixtral 8x22B：经典 MoE 范式

  • 架构：8 个大专家，每专家约 22B 参数。
  • 路由：每个 token 激活 2 个专家（top-2）。
  • 激活率：39B / 141B = 27.7%——比 DeepSeek-V3 高 5 倍。

MoE 路由核心代码（DeepSeek-V3 风格）

import torch
import torch.nn.functional as F

class DeepSeekMoERouter(nn.Module):
    """DeepSeek-V3 风格 MoE 路由器：Top-8 路由 + 共享专家"""
    
    def __init__(self, hidden_size, num_routed_experts=256, 
                 num_activated=8, num_shared=1):
        super().__init__()
        self.num_routed_experts = num_routed_experts
        self.num_activated = num_activated  # top-k
        self.num_shared = num_shared
        
        # 路由门控网络
        self.gate = nn.Linear(hidden_size, num_routed_experts, bias=False)
        
        # 共享专家（永远激活，所有 token 都走）
        self.shared_experts = nn.ModuleList([
            nn.Linear(hidden_size, hidden_size) for _ in range(num_shared)
        ])
        
        # 路由专家
        self.routed_experts = nn.ModuleList([
            nn.Linear(hidden_size, hidden_size) for _ in range(num_routed_experts)
        ])
    
    def forward(self, x):
        """
        Args:
            x: [B, L, D] 输入 hidden states
        Returns:
            output: [B, L, D] MoE 输出
        """
        B, L, D = x.shape
        
        # ========== Step 1: 计算路由分数 ==========
        router_logits = self.gate(x)  # [B, L, 256]
        
        # ========== Step 2: Top-8 专家选择 ==========
        # DeepSeek-V3 用 sigmoid + bias 而非 softmax
        routing_weights = router_logits.sigmoid()  # [B, L, 256]
        
        # 选出 top-8 专家
        topk_weights, topk_indices = routing_weights.topk(self.num_activated, dim=-1)
        # 归一化权重
        topk_weights = topk_weights / topk_weights.sum(dim=-1, keepdim=True)
        
        # ========== Step 3: 路由到选中的专家 ==========
        routed_output = torch.zeros_like(x)
        for i in range(self.num_activated):
            expert_idx = topk_indices[:, :, i]  # [B, L]
            expert_weight = topk_weights[:, :, i:i+1]  # [B, L, 1]
            
            # 按 expert 聚合 token（提升效率）
            for expert_id in range(self.num_routed_experts):
                mask = (expert_idx == expert_id)  # [B, L]
                if mask.any():
                    tokens_for_expert = x[mask]  # [N, D]
                    expert_out = self.routed_experts[expert_id](tokens_for_expert)
                    routed_output[mask] += expert_weight[mask] * expert_out
        
        # ========== Step 4: 加上共享专家输出 ==========
        shared_output = sum(expert(x) for expert in self.shared_experts)
        
        return routed_output + shared_output
    
    def aux_loss(self, router_logits):
        """DeepSeek-V3 无辅助损失路由器"""
        # V3 通过动态 bias 调整负载，无需 aux loss
        # 见论文 3.2 节：auxiliary-loss-free balancing
        return 0.0
核心洞察：DeepSeek-V3 用「细粒度专家 + 共享专家 + 无辅助损失路由」三招，把激活率压到 5.5%——这是 2025 年 MoE 架构的最优工程平衡点。Qwen3 走「中等粒度 + 思考模式切换」路线，更适合可控成本 + 可变深度的 Agent 场景。Mixtral 8x22B 虽然优雅简洁，但 27.7% 的激活率在 2026 年已不具备性价比——这是为什么 Mixtral 团队在 8x22B 之后再未发布新旗舰 MoE 的根本原因。

批量推理成本计算器（代码片段）

"""
2026 Q2 四大旗舰模型成本对比计算器
输入：每月输入/输出 token 量、缓存命中率
输出：每月总成本 + 最优模型推荐
"""

MODELS = {
    "GPT-4o":            {"input": 2.50,  "output": 10.00, "cache_hit": None},
    "GPT-4.5":           {"input": 75.00, "output": 150.00,"cache_hit": None},
    "Claude-3.5-Sonnet": {"input": 3.00,  "output": 15.00, "cache_hit": None},
    "Claude-3.5-Haiku":  {"input": 0.80,  "output": 4.00,  "cache_hit": None},
    "DeepSeek-V3":       {"input": 0.14,  "output": 0.28,  "cache_hit": 0.014},
    "Qwen3-235B-A22B":   {"input": 0.30,  "output": 1.20,  "cache_hit": None},
    "Qwen3-30B-A3B":     {"input": 0.10,  "output": 0.30,  "cache_hit": None},
}

def monthly_cost(model_name, input_tokens, output_tokens, cache_hit_ratio=0.0):
    """
    计算每月推理成本（单位：美元）
    Args:
        model_name: 模型名
        input_tokens: 每月输入 token 数
        output_tokens: 每月输出 token 数
        cache_hit_ratio: 缓存命中率 (0-1)，仅 DeepSeek-V3 支持
    """
    m = MODELS[model_name]
    # 输入成本（处理缓存）
    if m["cache_hit"] and cache_hit_ratio > 0:
        input_cost = (input_tokens * (1 - cache_hit_ratio) / 1e6 * m["input"] +
                      input_tokens * cache_hit_ratio / 1e6 * m["cache_hit"])
    else:
        input_cost = input_tokens / 1e6 * m["input"]
    # 输出成本
    output_cost = output_tokens / 1e6 * m["output"]
    return input_cost + output_cost


# 示例：月活 100 万用户的产品，平均每次对话 1K input + 500 output
SCENARIOS = {
    "小规模 PoC":      {"input":  100 * 1e6, "output":  50 * 1e6},
    "中型 SaaS":       {"input":  1000 * 1e6,"output":  500 * 1e6},
    "大型平台":        {"input":  10000 * 1e6,"output": 5000 * 1e6},
}

for scenario, tokens in SCENARIOS.items():
    print(f"\n{'='*50}")
    print(f"场景：{scenario}（月 {tokens['input']/1e6:.0f}M input + {tokens['output']/1e6:.0f}M output）")
    print('='*50)
    results = []
    for model in MODELS:
        cost = monthly_cost(model, tokens["input"], tokens["output"], 
                           cache_hit_ratio=0.7 if "DeepSeek" in model else 0)
        results.append((model, cost))
    results.sort(key=lambda x: x[1])
    for model, cost in results:
        print(f"  {model:<22} ${cost:>12,.2f}")
    cheapest = results[0]
    savings = results[-1][1] - cheapest[1]
    print(f"  💰 最优：{cheapest[0]}，相比最贵模型节省 ${savings:,.0f}/月")

展望 · Outlook

2026 H2 的三个观察点

1. NSA 是否成为标准组件？

ACL 2025 最佳论文光环下，NSA 有望成为下一代 Transformer 的标配注意力模块。但这需要 PyTorch/JAX 等框架原生支持三路并行，目前仍需手写 CUDA kernel。预计 2026 Q4 会有原生支持落地。

2. MoE 激活率物理极限在哪？

3% 的激活率已逼近 HBM 访存与计算单元的平衡点。继续下降需突破内存墙——可能路径包括：① 专家合并（merge similar experts）；② 动态激活（按输入难度自适应）；③ 神经架构搜索（NAS）自动搜索最优激活率。

3. 端侧 MoE 的可能性

Qwen3.6-35B-A3B 已展示「3B 激活 / 35B 总量」的可能性。若进一步压缩到 1B 激活 / 10B 总量，将可在高端手机本地运行——「端侧 Agent」将迎来硬件级的物质基础。

终极判断：MoE + 稀疏注意力的组合，本质上是把「计算」从「模型本身」剥离到「路由策略」。这让大模型从「重资产训练」转向「轻资产推理」成为可能——AI 应用的边际成本结构正在被重写。
