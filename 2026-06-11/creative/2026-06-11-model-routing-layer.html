00 / 核心命题

一个正在「前台化」的后台

2025—2026 年,我们正在目睹一轮结构性的位移:模型路由(Multi-Model Routing)从藏在 SDK 里的中间件,跃迁为产品差异化竞争的「前门」。

当「选哪个模型」比「写哪个 prompt」更影响最终结果,选择权就必须交还给用户或显性化的策略层。

所谓「前台化」,指三层迁移:① 决策显性化(策略可见、可解释);② 触点产品化(用户场景内嵌路由逻辑);③ 资产方法论化(从黑魔法变成可被复制的工作流)。本份创意信息图,以四个并列的演化切片,呈现这条「从后台到前台」的产品化路径。

03 / CASE 02

Apple · 统一推理入口

在 iOS 26 之后(跳过 iOS 19 / 20 命名),Apple 把「调模型」做成了跨 App 的系统级契约。

App Intents

从「打开 App」到「表达意图」

App Intents 框架让用户不必进入特定 App,只需在 Siri / Spotlight / 系统搜索中表达意图,系统自动选择最佳 App + 最佳模型处理。

  • 统一动作定义:每个 App 暴露「Intent」声明
  • 跨 App 链式调用:一个 Intent 可触发多个 App 协同
  • 系统级缓存与去重,降低模型重复调用
  • 与 Shortcuts / Focus Filter 深度融合
Foundation Model · Apple Intelligence

本地优先 + 云端兜底

iOS 26 起,Apple Intelligence 默认在端侧 Foundation Model 上推理,复杂任务透明地上云(Private Cloud Compute),用户和 App 都无需关心模型细节。

  • 端侧 3B 参数 Foundation Model,处理 90% 日常任务
  • Private Cloud Compute 兜底复杂推理,数据不落盘
  • 第三方 App 可经由 App Intents 间接使用,无需自接 API
  • 系统按电量 / 网络 / 隐私级别智能调度
"

Apple 的「前台化」路径,是把模型选择权完全收归系统,让 App 和用户都站在「前台」之外 — 这是一种「路由即操作系统」的极端形态。

核心观察 · Liquid Glass 设计与 App Intents 升级共同构成 iOS 26 的「模型无感」体验

05 / CASE 04

Boris Cherny · 长任务路由五原则

Anthropic 工程师、Claude Code 创造者之一 Boris Cherny 的方法论 — 把「长任务里怎么调度模型」总结成可被工程团队复用的工作流。

1
①

任务分解

把长任务切成独立可验证的子任务,每个子任务有明确输入 / 输出 / 验收标准。

Decomposition
2
②

模型选择

按子任务难度分配不同模型 — 简单任务用 Haiku 级,推理任务用 Sonnet / Opus,动态升降级。

Model Tiers
3
③

上下文管理

用 Plan Mode、子 Agent 隔离上下文,避免主任务上下文被噪声子任务污染。

Context Hygiene
4
④

容错重试

每个子任务有明确重试上限与降级路径,失败时回到上一步或换模型重派。

Resilience
5
⑤

结果聚合

各子任务独立产物在主流程中校验、合并、归档,主模型只做最终整合而非执行。

Aggregation
"

长任务的核心不是「让模型更聪明」,而是「让正确的子任务,找到正确的模型」 — 这就是路由思维的工程化表达。

Boris Cherny · Anthropic · Claude Code 核心贡献者 · 2025—2026

08 / 创艺结语

下一个「前台化」会发生在哪?

把视角从「4 个案例」拉远,模型路由的「前台化」可能是 2026 下半年最值得追踪的产品演化方向。

①

趋势 · 路由决策 UI 化

更多产品会把「调哪个模型」从开发者配置,变成终端用户可见的策略面板(类比 CDN 缓存策略的演化)。

②

趋势 · 模型无感的 OS 层

Apple 的路径会被 Android / 鸿蒙 / Windows 跟进,系统级 AI 调度成为新一代 OS 的标配能力。

③

趋势 · 企业级场景派单

Box 式「按场景自动派单」会成为企业 SaaS 的差异化标配,「智能路由」成为产品页的关键词。

④

趋势 · 方法论资产化

Boris 式工程方法论会被更多厂商整理为白皮书 / 课程 / 内部 SOP,成为组织能力的护城河。
