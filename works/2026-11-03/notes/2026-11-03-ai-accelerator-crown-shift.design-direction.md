## 0. 一句话视觉命题

**这是一份"一个人在深夜把两张份额图来回拖"的屏幕，不是一份报告。**

全篇只用一个母题：**台阶**。第二段的三项供给收紧是三级向内收窄的台阶，第四段的收尾把同一个母题闭合成"王座下面被凿出的一级台阶"。所有版式变化都服务于这条台阶线，不引入第二套装饰系统。

## A. 色彩策略

### A0. 物理场景（唯一光源决定全部色值）

**一个做半导体产业判断的分析师，夜里十点坐在工位前，台灯已关，屏幕是房间里唯一的光源。他要在三米外扫到 `34%` 这个数字，又要在近处读清「12 层改 8 层」这种小字。**

由这一场景推出三条不可违反的规则：

1. 底色必须是**屏幕自发光**的深色（夜里浅底刺眼，浅底还会把房间杂光反射回内容上）。
2. **不用毛玻璃**：夜里背景杂乱，毛玻璃会把杂乱糊进正文，读者看不清数字。
3. 大数字与小字**共用同一套前景色**，靠字号和字距分层，不靠颜色分层 —— 颜色只用来编码"公司身份"和"强调"两件事。

### A1. 八个色角色（唯一色板，共 8 个 hex）

| # | 角色 | HEX | 放在哪个底色上 | 对比度 | 判定 |
|---|------|-----|----------------|--------|------|
| 1 | 背景（画布） | `#0E1116` | — （自身底） | — | 深墨蓝黑，非纯黑，减少 OLED 死黑与黑字边界的"洞感" |
| 2 | 面板底（轨道/说明块/闸门区） | `#161B22` | 叠在 `#0E1116` 上 | 1.16:1（面板与画布的分隔，属**装饰性**边界，不承载信息） | 仅作分区，不承载文字 |
| 3 | 正文 | `#E9EDF3` | `#0E1116` | **16.10:1** | ✅ 正文级，远超 4.5:1 |
| | | | `#161B22` | **14.72:1** | ✅ |
| 4 | 次级文字（眉标/注记/单位/来源） | `#A8B4C3` | `#0E1116` | **8.99:1** | ✅ 正文级（不降到 4.5 以下） |
| | | | `#161B22` | **8.22:1** | ✅ |
| 5 | 英伟达条 | `#76B900` | `#0E1116` | **7.84:1** | ✅ 图形级 ≥3:1，同时可作文字色 |

| 6 | 华为条 | `#F2605F` | `#0E1116` | **5.96:1** | ✅ 图形级 ≥3:1，且 ≥4.5:1，可安全作文字色 |

对比度用 WCAG 2.x 相对亮度公式计算（`python3` 脚本，sRGB → 线性化 → L = 0.2126R + 0.7152G + 0.0722B → (L1+0.05)/(L2+0.05)），数值已逐项核对。

### A2. 色板纪律（写死，避免后期漂移）

- **全件只有 8 个 hex。** 除此之外的明暗变化只允许两种派生：
  - 分隔线：`#A8B4C3` @ 20% 叠在 `#0E1116` → 实色 `#2D3239`，对比度 1.47:1，**仅装饰**，不承载信息。
  - 推演区斜纹：`#E9EDF3` @ 12% 叠在 `#161B22` → 实色 `#2F343B`，对比度 1.38:1，**仅装饰**，识别靠标签与前缀，不靠纹理（见 F1）。
- **颜色只做两件事**：编码公司身份（绿=英伟达、红=华为、灰蓝=其他）；标出"收紧/缺口/当前值"（琥珀 `#F2A93B`）。琥珀全件不超过 6 处出现，且**只用于 4 个箭头端点 + 2 个当前值读数**。
- **禁止**：`linear-gradient` / `radial-gradient`（含文字渐变与条纹渐变，斜纹一律用内联 SVG `<pattern>` 的 1px 描边线实现）、`backdrop-filter`、阴影堆叠（只用 1px 描边 + 2px 圆角）、任何彩色渐变背景。
- **绿色与红色的语义不可互换**：绿=英伟达、红=华为在第二、三、四段必须保持一致；琥珀色永远不表示"某一家公司"。
- **红/绿只用于图形与 ≥24px（或 18.66px 粗体）文字**；小字语义一律用 `#E9EDF3` / `#A8B4C3`，避免红绿在正文小字上读成"错误/正确"。

## B. 字体策略

### B1. 字体栈（全部离线可得，无外链字体）

| 用途 | 栈 |
|------|-----|
| 中文正文 / 标题（系统 UI 栈） | `-apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Source Han Sans SC", "Noto Sans CJK SC", "Source Han Sans CN", sans-serif` |
| 数字（独立数据位，等宽） | `ui-monospace, "SF Mono", Menlo, Consolas, "DejaVu Sans Mono", "Liberation Mono", monospace` |
| 拉丁/数字内嵌正文 | 跟随 UI 栈（PingFang SC 的西文与数字已足够） |

- 「思源黑体」以 `Source Han Sans SC` / `Noto Sans CJK SC` 两种命名并列写入，兼容 Linux 与 macOS 两种安装名。
- **不使用** 衬线体（Georgia）与任何中文衬线：本件是仪表盘语感，衬线会把它推向"杂志/研究报告"，违反"非研究类模板"。等宽体只用于数据位，不用于中文。
- `font-variant-numeric: tabular-nums` + `font-feature-settings: "tnum" 1`：所有会变化的数字用等宽数字，防止数值跳动时条形图左右抖动。

### B2. 四级字号规格

| 级别 | 用途 | 桌面 ≥1024px | 375px | 字重 | 行高 | 字距 |
|------|------|-------------|-------|------|------|------|
| **L1 标题** | 段标题 H2 | 32px | 24px | 700 | 1.25 | `-0.01em`（CJK）/ `-0.02em`（数字） |
| | 眉标 eyebrow（"01 / 02"、单位） | 13px | 12px | 600 | 1.2 | `0.16em` |
| | Hero 大数字 | `clamp(72px, 9vw, 112px)` | `clamp(56px, 18vw, 96px)` | 600 | 1.0 | `-0.03em`，`tabular-nums` |
| **L2 正文** | 叙述段落 | 17px | 16px | 400 | 1.75 | `0.01em` |
| | 收尾金句 | 24px | 20px | 600 | 1.6 | `0` |
| **L3 数字** | 份额当前值 | 28px | 22px | 600 | 1.2 | `-0.01em`，`tabular-nums` |
| | 数据标签（条旁名称、单位） | 14px | 13px | 500 | 1.4 | `0.02em` |
| | 表格内数字（等宽栈） | 13px | 12.5px | 400 | 1.5 | `0` |
| **L4 来源注记** | 来源、口径、时间 | 12.5px | 12px | 400 | 1.6 | `0.01em` |

- **测量宽度**：正文 `max-width: 680px`（17px × 40 字/行），落在 34–40 字/行的中文舒适区间。
- **中英混排**：中文与拉丁/数字之间留一个半角空格（数据位用等宽栈时同理），避免中西文贴死。
- **数字分级原则**：嵌在中文句子里的数字跟随 UI 栈；成组排列的表格数字与代码式读数（`+10–20%`、`6–8`）用等宽栈，保证列对齐。

## C. 版式骨架

### C1. 网格与宽度

| 项 | 规格 |
|----|------|
| 最大宽度 | **1120px**（交互段与 hero），**680px**（正文段测量宽度） |
| 栅格 | **8 列**：列宽 119px + 沟槽 24px（8×119 + 7×24 = 1120） |
| ≤480px 栅格 | **4 列**：`grid-template-columns: repeat(4, 1fr)`，沟槽 12px，内容宽 343px（375 − 16×2） |
| 页面左右留白 | 桌面 24px，375px 16px |
| 段间距 | 桌面 `padding-block: 112px`；375px `64px`；第 4 段收尾另加（上 160px / 下 120px） |
| 圆角 | 面板 8px，轨道 2px，条本体 0 |
| 描边 | 面板 `1px solid rgba(#A8B4C3, .20)`，不放阴影 |

**为什么 8 列而不是 12 列**：全篇是单栏纵向叙事 + 一个宽交互段。12 列在 1120px 下每列 71px，中文段落跨 6 列会碎成半行，交互段的三方份额也要拆到 4 列各一根，条长不足 150px，读不出"此消彼长"。8 列让交互段能拿到 5 列（691px）做条形区。

### C2. 四段纵向节奏与视觉锚点

| 段 | 文案锚点 | 视觉锚点（具体形态） | 高度占比建议 |
|----|----------|---------------------|-------------|
| **01 开场** | 「英伟达仍占最大一块——但'最大'正在从 34% 滑向另一个数字」 | **大数字 + 刻度带**，不是饼图。左侧 `34%`（L1 Hero 数字，`tabular-nums`），其右一条 0–50% 的刻度尺：主刻度每 10%、次刻度每 2%，当前值 34% 处一枚实心 1px 白刻度 + 12px 数值；**刻度带右端 50% 处刻意留空**，只放一个 20px 空心圆 SVG + 12px 注记「另一个数字 → 见第三段」。眉标「2026 上半年 · 实际份额」 | 视口 1.0–1.2 倍 |
| **02 发展** | 份额易主与供给收紧同时发生（三条数据） | **三级台阶**。三项数据各画一根"区间条"，三条自上而下**向右缩进 24px**（375px 缩进 16px），形成向内收窄的阶梯，与第 4 段同源。旧值一律 1px 虚线描边 + `#A8B4C3`；新值实心填充 `#161B22` + 1px 描边；**收紧方向用 4 个 10×2px 琥珀色 SVG 箭头端点**标记（只有 4 处，全件琥珀用量之一） | 视口 1.6–1.8 倍 |
| **03 高潮** | 「算力王座竞速」交互 | **交互本体**：一条全局推演轨 + 三条份额条 + 两个供给闸门滑块（详见 D） | 视口 1.8–2.2 倍 |
| **04 收尾** | 「王座没有易主，是有人在王座下面凿了一级台阶」 | **金句 + 一幅 SVG 剪影**：160×120 视图框内的极简王座轮廓（手绘路径，纯描边 2px），王座正下方一级台阶被凿出**缺口只描边不填充**（琥珀 2px），缺口旁 12px 注记「缺口即新增供给」。金句 24px/600，2px 琥珀左边框。上方留白 160px | 视口 0.8–1.0 倍 |

### C3. 第三段在 375px 下的堆叠方式 —— **单栏堆叠（不是并排双栏）**

理由三条：

1. 375px 下并排双栏每栏仅 155px，"英伟达"三个字 + 数值就占满，条长不足 60px，读不出此消彼长。
2. 并排双栏要求读者视线左右横跳，与"竖屏单手下滑"的阅读姿势冲突。
3. 本段的真正交互是**一个连续量 t（实测 → 推演）**，本来就只需要一列条 + 一个把手，不需要两列。

具体堆叠（375px，从上到下）：

```
┌──────────────────────────────┐
│ 推演轨  2026H1 实测 ──── 推演  │  把手可拖，轨道高 44px 命中区
│ 34%        ━━━━━━━━━●        │  ← 把手 28px
├──────────────────────────────┤
│ 英伟达  ▓▓▓▓▓▓▓▓▓░░  33.8%  │  标签在上，条在下（375px 规则）
│ 华为     ▓▓░░░░░░░░░  21.4%  │
│ 其他     ▓▓▓░░░░░░░░  18.7%  │
├──────────────────────────────┤
│ 供给闸门                      │
│ CoWoS 提价   +15%  ├──●───┤   │
│ 设备交期      6 月 ├───●──┤   │
└──────────────────────────────┘
```

- **375px 标签规则**：标签置于条**上方**一行（13px），不设左侧标签列（宽屏才用左侧 96px 标签列）。这样条的轨道可占满 343 − 28（面板内边距）= **315px**。
- **宽屏（≥900px）双栏读法**：8 列网格切成三块 —— 左列（1–2 列，262px）= 2026H1 实测数值表；中段（3–7 列，691px）= 三条横条与推演轨；右列（第 8 列，119px）= 推演数值表。**条区标签列固定 96px**，条轨道 = 691 − 96 − 12 = **583px**。
- **量程**：条轨道满量程 0–50%（不是 0–100%，否则 34% 的条只有 196px，读不出差异）。**截断量程必须在轨道右端明写「量程上限 50%」**，这是诚实要求，不是可选项。
- **每根条上的两个端点刻度**：左端实心刻度 = 实测值，右端虚线刻度 = 推演值（推演值带区间，如 `~27% (24–29%)`）。"此消彼长"由这两枚刻度的相对位移读出，而不是靠条本身。

## D. 签名交互的形态与动效规格

### D1. 「王座王座竞速」推演轨（主交互）

**形态：自定义拖动把手（Pointer Events），不是分段按钮，也不是原生 `range`。**

- 分段按钮（"实测 / 推演"两枚按钮）只作为**键盘与读屏的等价路径**保留在把手之外（可见度由 JS 控制），因为它无法表达中间插值态。
- 原生 `range` 不选：无法在轨道上同时画"实测端点刻度 / 推演端点刻度 / 当前值"，且跨浏览器拇指样式不一致。
- 实现要点：`pointerdown` → `setPointerCapture` → `pointermove` 跟手 → `pointerup` 释放；把手 `role="slider"`，`aria-valuemin=0` `aria-valuemax=100` `aria-valuenow` `aria-valuetext="推演进度 60%"`；键盘 ←/→ ±2%，Shift+←/→ ±10%，Home/End 到 0/100。

| 场景 | 时长 | 缓动 |
|------|------|------|
| 拖动中（三条条 + 数值实时跟手） | **0ms**（拖动期间对所有条与数字关闭 `transition`） | 无 |
| 松手吸附到最近 10% 刻度 | **260ms** | `cubic-bezier(0.22, 1, 0.36, 1)` |
| 轨道两端标签（实测 / 推演）高亮交叉淡入 | **140ms** | `linear`（仅 `opacity`，不位移） |
| 数值文本跳变（rAF 插值写 `textContent`） | **300ms** | `cubic-bezier(0.33, 1, 0.68, 1)`（easeOutCubic） |

### D2. 「供给闸门」两个滑块

- **形态**：两个原生 `<input type="range">` + 自绘轨道（`appearance:none`；轨道高 4px、拇指视觉直径 14px、命中区 44×44px 用 padding 撑开）。选原生的理由：键盘、触摸、读屏、步进值全部免费获得。
- 参数与默认值：
  - CoWoS 提价幅度 `p`：0–30%，步进 1%，默认 **15%**。
  - 设备交期 `L`：3–9 个月，步进 1，默认 **6 个月**。
- **份额条用 CSS transition，不用 JS 逐帧。** 具体分工：
  1. 闸门改变的是**推演终值**，不是当前显示值。
  2. 拖动闸门时（`input` 事件）：终值端点刻度与推演表数值**直接写、0ms 跟手**；同时把新终值写进 CSS 自定义属性 `--nv-end` / `--hw-end` / `--ot-end`。
  3. 松手时（`change` 事件）：开启 `transition`，条与刻度用 **420ms `cubic-bezier(0.33, 0, 0.15, 1)`** 走到新位置。
  4. 文本数值用 `requestAnimationFrame` 插值 **300ms easeOutCubic**，只写 `textContent`，不写 `width`、不碰 DOM 结构。
- **条长必须用 `transform: scaleX()` 表达，不改 `width`**：`transform-origin: left center`，条本体为无圆角矩形，外层轨道 `overflow:hidden` + 2px 圆角负责裁切。这样宽度动画走合成层，不触发 layout，60fps 有保障（`width` 动画会每帧重排三条条 + 两个表）。
- **因果链必须可见**：闸门区上方一行 12px `#A8B4C3` 文字「拖动后改变的是推演终值」，并用一条 1px 虚线 SVG 连接器从滑块指向条区右端的推演刻度；用户必须能看出"我拖的是假设，被改的是未来那一端"。
- **占位映射模型（供创艺参考，必须在 UI 上标明是演示假设，非预测）**：
  - `t_supply = clamp(0.5 × (p/30) + 0.5 × ((L−3)/6), 0, 1)`
  - 华为份额 `+8pp × t_supply`（上限 +12pp）；英伟达份额 `−6pp × t_supply`；其他吸收余量。
  - 算力成本指数 `= 100 × (1 + p/100) × (1 + (L−6) × 0.03)`，在闸门区右侧显示为琥珀色当前读数（这是"供给对价格"的那条轴）。
  - 该组系数是**排版占位**，不是行业结论；若内容方给出真实推演值，替换终值表即可，交互与动效不变。

### D3. 段落入场与全件动效纪律

- 段入场：`opacity 0→1` + `translateY 12px→0`，**520ms `cubic-bezier(0.16, 1, 0.3, 1)`**，`IntersectionObserver` `threshold: 0.2` 触发；同段元素 stagger **70ms**。
- 全件**禁止无限循环动画**（无呼吸、无脉冲、无自动轮播）；所有动效一次性、可被打断。
- 只动 `transform` 与 `opacity`；不动 `width`、`height`、`top`、`left`、`box-shadow`；字距、字号动画一律不用（会触发布局重排）。
- 悬停反馈仅用 `opacity` / `border-color` 变化，120ms `linear`。

### D4. `prefers-reduced-motion: reduce` 降级规格

| 项 | 降级后 |
|----|--------|
| 全局 | `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important; transition-duration: .01ms !important; scroll-behavior: auto !important; } }` |
| 段入场 | 直接可见，无淡入上移 |
| 推演轨拖动 | **保留可用**，跟手不变（关掉的只是动画，不是功能）；**取消松手吸附**，松手即停在当前位置 |
| 份额条 | 闸门变化时瞬时跳到终值，不做 420ms 过渡 |
| 数值文本 | 不滚动，直接显示终值 |
| 保留的信息 | 推演值仍带 `~` 前缀、斜纹底、虚线刻度与"推演 · 情景假设"标签 —— **动效降级不等于信息降级**；另加一行 12px 静态说明「推演值随闸门参数变化」 |
| 不做的事 | 不用"闪烁提示"替代动画；不使用 `alert` 式突变 |

## E. 反面清单（最容易滑向的 3 个 AI 俗套 + 具体避开做法）

### E1. 俗套：玻璃拟态卡片阵列 —— 深色半透明圆角卡 + 彩色光晕，三张并排

- **本件的具体风险**：第三段三个滑块/两个闸门天然会被排成"三张卡"。
- **避开做法**：全件 `backdrop-filter` 出现 0 次；面板是 `#161B22` 实底 + 1px 描边 + 8px 圆角 + 0 阴影；**第三段不做任何并排等宽卡片**，改为一列推进（推演轨 → 份额条 → 闸门滑块），闸门两个滑块上下排列、各占整行；第二段的三项数据是**向右缩进的阶梯**，不是三张并排卡；圆角上限 8px，不出现 16/24px 大圆角。
- **可检查判据**：交付文件里 `backdrop-filter` 出现次数 = 0；`border-radius` 唯一值集合 = {8px, 2px}。

### E2. 俗套：发光渐变标题 + 居中大图标 hero —— 紫蓝渐变字 + 中心放一个巨大发光图标

- **本件的具体风险**：第 4 段的"王座"极易被做成居中大图标 + 光晕。
- **避开做法**：**全件 `linear-gradient`/`radial-gradient` 出现 0 次**（含文字渐变、条纹渐变）；hero 是**左对齐**的 `34%` 大数字 + 刻度带，没有居中图标；第 4 段的王座是一幅 160×120 的**手绘描边剪影**，放在金句**右侧 32px**（375px 下移到金句下方右对齐），不放大到满屏；强调只用琥珀实心小方块（4px 高的下划条）与 2px 左边框，不做发光。
- **可检查判据**：全文无 `gradient` 关键字；无 `text-fill-color: transparent`。

### E3. 俗套：通用"科技感"装饰 —— 点阵网格背景、粒子连线、发光圆环、emoji 图标、假数据仪表盘

- **本件的具体风险**：算力题材最容易掉进"深色 + 网格 + 霓虹 + 🚀/📈"这套通用 AI 视觉。
- **避开做法**：背景是**纯色 `#0E1116`**，无网格纹理、无粒子、无光斑、无噪点；所有装饰只服务于读数（刻度、端点、箭头、缺口），不做纯装饰图形；**图标系统 = 手绘内联 SVG**：`24×24` 视图框、`1.5px` 描边、`currentColor`、圆角端点（`stroke-linecap: round`），全套只做 6 枚：双箭头把手、收紧箭头、刻度游标、空心圆（未揭晓目标）、缺口标记、"≠"口径分歧标记；**不使用任何 emoji 字符**作为图标或装饰；不做圆环仪表盘、不做"实时在线"闪烁数字。
- **可检查判据**：HTML 中不出现任何 `U+1F300–U+1FAFF` 字符；`<svg>` 数量与 6 枚图标一致，无第 7 枚装饰性图形。

## F. 诚实的视觉（让用户看得难受的地方）

### F1. 推演与实测必须是两种"材质"，不是两种"颜色"

- 推演侧：45° 斜纹（内联 SVG `<pattern>`，1px 线、6px 间距、`#E9EDF3` @12%）、条与端点刻度改虚线、每个数值加 `~` 前缀、面板顶部固定一枚标签「推演 · 情景假设，非预测」。
- 实测侧：实底、实心刻度、无前缀、无标签干扰。
- **诚实点**：斜纹实色 `#2F343B` 对面板底只有 1.38:1，是装饰性差异，识别责任由**文字标签与 `~` 前缀**承担，不靠纹理让人猜。设计师必须承认这一点，不能宣称"加了底纹就一眼可辨"。
- 推演值一律给区间（`~27% (24–29%)`），不给单点。

### F2. 口径分歧处让两条说明"打架"，不做合并

- 在闸门区下方固定一个"来源对照"块：左栏 = CoWoS 封装代工报价口径（实线左边框），右栏 = 芯片设备交付周期口径（虚线左边框），中间一枚 20px 的 `≠` SVG 标记。
- 两栏各自写明统计口径与时间窗口（例如"封装代工报价口径，2026H1"与"交付周期口径，含订单积压"）。
- 当用户把 `p` 与 `L` 同时推到高档时，中间 `≠` 的描边变为琥珀 2px，并在下方出现一行 12px 文字「两条口径不同，不能相加成一个供给紧张指数」。
- **诚实点**：本件**拒绝**提供一个"供给紧张指数"这类合并指标。读者会因此觉得屏幕没有给出一个干脆的答案 —— 这正是数据本身的状态。

### F3. 不为了戏剧性制造反转，缺口不填满

- 当闸门推到顶、推演终值仍不足以让华为超过英伟达时，直接显示「本情景下首位未变」；**不得**为了高潮段戏剧性强行调参让曲线交叉。
- 开场刻度带右端在第 3 段之前**不显示任何目标数字**，只留一个空心圆；第 4 段才揭示推演终值，且终值带区间。
- 第 4 段王座下的台阶缺口**只描边不填充**，表示"供给增加已发生，但尚未落到地面"；缺口旁 12px 注记「缺口即新增供给」。
- 收尾金句之后不再加任何总结段或数据回看 —— 留白本身就是诚实的设计选择。
