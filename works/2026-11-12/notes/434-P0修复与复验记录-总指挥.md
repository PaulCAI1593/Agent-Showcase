## 一、缺陷

1. 现象：滑块推到 5 次点亮安全轨后，`.pane__wait` 遮罩仍 `opacity:1`、`visibility:visible`、`z-index:2` → 「按这句执行」真实点击被拦截（Playwright 点击超时，`.cmd` 仍为 `cmd`）。对照实验：移除遮罩后同一点击成功（`cmd` → `cmd is-rewritten`）→ 页面 JS 正确，样式被覆盖。
2. 第二处：改写后 `.floor__arrow--a`（指 3 号台）被强制 `opacity:1`，与 `.floor__arrow--b`（5 号台）同时亮 → 目标指向歧义。
3. 根因：`tools/add_backlink.py:dead_rules()` 把「状态条件式」的 `opacity:0` 规则判为永久隐藏的死规则 → 注入 `<style id="showcase-rescue">` 以 `!important` 覆盖。本页命中 `body.ignited .pane__wait` 与 `.cmd.is-rewritten .floor__arrow--a`。`add_backlink.py` 对已含 marker 的文件直接跳过 → 该注入样式永不刷新，陈旧覆盖长期驻留。全库 41 件作品带该注入样式。

## 二、修复（4 处编辑，+47 B）

1. `:root` 增 `--state-off:0;`
2. `body.ignited .pane__wait{opacity:0;visibility:hidden}` → `{opacity:var(--state-off);visibility:hidden}`
3. `.cmd.is-rewritten .floor__arrow--a{opacity:0}` → `{opacity:var(--state-off)}`
4. 移除本页陈旧的 `<style id="showcase-rescue">…</style>`（只含上述两条误覆盖）

依据：`add_backlink.dead_rules()` 离线验证——替换后本页 dead 列表只剩 `/* ── hud ── */ .hud` 一条（该条为流水线设计意图，HUD 显隐由 JS 控制）。
