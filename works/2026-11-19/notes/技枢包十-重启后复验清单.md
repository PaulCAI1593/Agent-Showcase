## V1 · ① `next_run_at` 刷新进 `finally`

### 判据（核心）

**失败轮次结束后，`next_run_at` 必须被推进**，且满足：

```
next_run_at > last_run_at     且    next_run_at 指向未来时刻
```

改前的缺陷：刷新写在 `_execute_once` 之后、**不在 `finally` 内**（`manager.py` 改前 1076–1085 行），
失败轮抛异常时刷新被跳过 → `next_run_at` 停在旧值（曾显示 11-17 08:00 / 11-16 14:00 已过期）。
改后：`manager.py:1082-1087` `finally:` 内刷新（实测行号）。

### 三种取数方法（按可信度排序）

**方法 A — 生产失败轮（唯一能证明「进程内行为」的方法，通过才算 V1 通过）**

等一个**自然失败**的 cron 轮次（不手动触发）。轮次结束后跑：

```bash

qwenpaw cron state <JOB_ID> --agent-id default
# 期望：last_status = error / stream_idle_timeout 相关，
#       next_run_at 是未来时刻，且 > last_run_at

python3 - <<'PY'
import json
for jid, name in [("55dfedc5-2c11-45ea-850f-4c9cba69e0cd","识别"),
                  ("bf95cdb7-a3ab-4218-b050-6cd6da2f98a7","新闻"),
                  ("8fd94954-4c63-4e29-8ba1-52c6a9d2bb40","股市")]:
    recs = json.load(open(f"jobs_history/{jid}.json"))
    last = recs[0]
    if last["status"] == "success":
        continue

    print("   error=", str(last["error"])[:200])
PY
```

**通过证据**（贴原文）：`next_run_at=<未来时刻>` + `last_run_at=<失败轮时刻>` + 两者差值合理。

**方法 B — 离线功能自测（已实跑，只证明磁盘代码，不证明进程已加载）**

## V2 · ② 流空闲超时与真超时分开归类

### 判据（三处必须同时成立）

1. **失败轮的 `error` 文案**形如：
   ```
   StreamIdleTimeoutError: model stream idle, run elapsed <实测秒>s (cron limit 2400s): LLM stream for <model> produced no content for 30s
   ```
   → 含 **实测耗时**，**不是** `timed out after 2400s`（那是配置值，改前的误标）。
2. **`inbox_traces` 对应 run 的 `status` = `stream_idle_timeout`**（不是 `timeout`、不是 `error`）。
3. **真超时**（超过 `timeout_seconds`）仍记 `status=timeout`，文案 `timed out after <实测>s (limit 2400s)`。

**代码位置（实测行号）**：
- `qwenpaw/app/crons/executor.py:382-407` → `except StreamIdleTimeoutError` → `finalize_trace(status="stream_idle_timeout")`
- `qwenpaw/app/crons/executor.py:408-436` → `except asyncio.TimeoutError` → `status="timeout"` + `CronExecutionTimeout(elapsed_seconds=…)`
- `qwenpaw/app/crons/manager.py:1204-1212` → `except StreamIdleTimeoutError` → `st.last_error = f"StreamIdleTimeoutError: {exc}"`
- `qwenpaw/app/crons/manager.py:1213-1247` → `except asyncio.TimeoutError` → `st.last_error = f"TimeoutError: {exc}"`

### 生产取数命令

            print(os.path.basename(f), "|", r["run_at"], "|", r["status"])

# ② 看 trace 的 status（按 job_id 过滤）
python3 - <<'PY'
