接入层正从应用内部长到操作系统外部

纵向叙事

三级跳：智能体先是被嵌进某个 App；然后被请进 IDE；如今，它开始被操作系统接受为「外部常驻人员」。每一次外移，授权门槛都被抬高一层。

阶段 1 · 应用内置AI 长在 App 里

苹果将 AI 助手嵌入 Keynote、Pages、Numbers 与 Logic Pro：AI 仍是应用内的产品功能，没有系统层面的独立身份。发证权由单个应用私自签发，别家进不来。

阶段 2 · IDE 并发IDE 转型为 agent 宿主

谷歌向第三方 AI 智能体开放 Android Studio，推出「自带智能体」架构：一个 IDE 可同时签发 40 多张证。供应商锁定开始松动，开放协议成为通用门票。

阶段 3 · 操作系统外部OS 把钥匙递到门口

苹果在 macOS 27 上首次支持 MCP：外部智能体可直接在 App 内读取内容、执行编辑与自动化操作。发证机关上移到操作系统，沙箱与治理成为新的必答题。

    托管 harness vs 自建 agent 循环

    两种路径

    拿证有两条路：把编排、工具、上下文与沙箱整体外包给托管方（微软 Foundry 的 Copilot Harness）；或者用 Cursor Agent SDK 自建循环、自己给自己当监督。

    托管 微软 Foundry · Copilot Harness

    编排平台托管，开箱即用
    工具平台托管，统一调度
    上下文平台托管，自动维护
    沙箱平台托管，统一隔离
    代价让渡主控权，锁定在平台侧

    自建 Cursor · Agent SDK

    定位把编码 agent 循环开放为可嵌入产品的服务
    胜任力"agent 的胜任力是 Cursor 的问题"
    监督"agent 的监督是你自己的"
    定价尚未发布可建模的按调用定价
    代价先上线的团队只能自己摸索账单
